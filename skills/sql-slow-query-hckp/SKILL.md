# 慢查询排查思路

本技能为**免费**知识型技能：提供方法论与模板，不涉及付费服务。

## 适用场景
接口突然变慢，只知道是数据库，不知道该从哪条语句查起。

## 核心方法
先抓到具体语句，再看执行计划确认是否走索引与扫描行数，最后改写或加索引。

## 标准步骤
1. 先定位：打开慢日志或从监控里抓到具体语句与耗时
2. 复现：带真实参数单独执行，确认耗时可重现
3. 看执行计划：关注类型、扫描行数、是否用上索引、有无临时表
4. 查索引：过滤与排序字段是否有合适索引、是否失效
5. 改写：减少返回列、拆分大分页、避免函数在字段上
6. 验证：改完对比耗时与扫描行数，留记录

## 可直接套用的模板
```
1 定位（语句 + 耗时 + 频次）｜ 2 复现 ｜ 3 执行计划要点
4 索引核对 ｜ 5 改写方向 ｜ 6 验证与记录
```

## 常见错误
- 没定位到具体语句就凭感觉加索引
- 在字段上套函数导致索引失效
- 改完不复测直接上线
