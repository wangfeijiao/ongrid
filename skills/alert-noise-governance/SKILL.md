# 告警噪音治理（Alert Noise Governance）

**问题**：监控建起来了，告警越加越多，用户开始无视告警——直到真故障躺在一堆噪音里没人看见。
**本技能的命题**：**误报不是"小打扰"，而是一种会摧毁整条告警通道的故障**。狼来了喊三次，第四条真狼就没人信。

> 一句话总纲：**告警的每一次触发，都必须能被解释、被复现、被修复**——解释不了、复现不了、修不掉的那次触发，就是误报，必须治，不能忍。

## 一、触发条件

- 收到"这告警一直响，但没什么事"、"别总提醒我"这类反馈
- 新写/新改一个哨兵、看门狗、健康检查、巡检脚本
- 排查一个"可能是误报"的告警，需要定性
- 告警量上升、去重失效、同根因反复开单

**不适用**：如何设计通知/告警的通道与回执闭环（拆分为独立主题，见相关技能）。

## 二、定性第一原则：先查责任方，再下结论

误报处置的第一动作**不是**改代码，是**取证**：

1. **读被测对象本身**——不读日志摘要、不读文件名、不读缓存、不读"上次也这样"。
2. **先假设告警是对的**，找它成立的条件；找不到成立条件，才升格为误报。
3. **结论必须带证据**：原始报错原文 / 进程与端口事实 / 时间线 / 退出码。禁止"我感觉是误报"。
4. 定性完成后**同步给被误伤的人**（若已打扰用户，当场更正 + 说明根因），不要静默修完当没发生过。

> 反面教材：用「用户组没变 ⇒ 那条命令从没跑过」来推断授权未发生——写授权文件根本不改变用户组，推理链断裂，结论完全反了。

## 三、误报十二型（每型：症状 → 实证 → 修法）

| # | 类型 | 判据症状 | 修法 |
|---|---|---|---|
| 1 | **无重试 / 无窗口期容忍** | 一次性尝试失败即判"服务挂了"；服务启动要 60 秒，探针第 3 秒撞进去 | 首次失败**先复检一次**（给足窗口期预算），复检通过 ⇒ 静默；自愈动作带 3 次重试 |
| 2 | **自愈成功也报** | 自愈脚本 rc=0 却打印"已修复/已拉起"，非空输出被当成异常投递，每 5 分钟刷屏 | **自愈成功 = 零输出**；只有"拉起失败"才产生输出 |
| 3 | **判据 TOCTOU** | 取"刷新前快照"与"刷新后的结果"比严格相等 ⇒ 期间只要有正常推进就恒判失败 | 复判**按现役状态重算**，与阈值同口径；判据写成纯函数、可单测 |
| 4 | **口径不一致** | 同一对象两个探针两套判据（一个按偶发静默、一个按硬失败告警）⇒ 必有一个在喊 | 同一对象的判据**收敛到唯一事实源**（一个列表、一个阈值、一处代码） |
| 5 | **计数 / 正则放大** | 宽 pattern 一命中就计数；统计变量写在循环外只算最后一份；正则不覆盖真实文件名（带点号、带哈希） | 计数口径与"业务语义"对齐；统计变量必须在正确层级；正则用**真实文件名**回归 |
| 6 | **把间接信号当判别性证据** | 用文件名里的时间戳当 mtime；用"卡片当前渲染"判断用户是否点过；用目录数当文件数 | 时间类断言必须 `stat` 真实文件；交互状态必须查**回调事件**；计数必须读被测对象 |
| 7 | **窗口 / 排班语义不符** | 只在 09:00–21:59 跑的作业，夜间按 24h 判"停跳"；排班从每小时收紧到每 10 分钟，`last_run` 还是旧节拍 ⇒ 一次性假告警；月级排班用周级阈值 | 判据**窗口感知**：解析调度表达式，先判"此刻是否应在窗口内"；排班变更后的第一个周期设宽限期 |
| 8 | **环境 / 拓扑漂移** | 网络模式变更后旧网关地址失效；同一脚本三份副本，跑的是旧版；元数据注释跨环境不同步 | 地址与路径**单一事实源 + 漂移哨兵**；多副本必须 md5 对齐 + 改动后跑**实际执行位**验证 |
| 9 | **错误信息误导** | 所有出网超时被统一报成"限流"，"限流"被统一报成"服务过载" ⇒ 排查方向被带偏 | 错误分类**不得混淆不同根因**；报错文案必须指向真实层（网络层 / 服务层 / 数据层） |
| 10 | **「无法判定」退化成「长期挂账」** | 存量历史问题无法立刻判定，于是被长期挂账、每轮刷群 | 设**判定线**：规则上线时刻之前的历史残留 = 存量，不入实时告警；给存量单独的收敛口径 |
| 11 | **去重键缺陷** | 去重语义是"已催办"，实现写在"尝试之后" ⇒ 失败也烧掉去重位、真正的责任方被静默；指纹只取名字 ⇒ 假警与真退化共用一键 | 去重位**只在成功路径写**；指纹必须含"哪一项 + 什么形态"；失败与成功分开记账 |
| 12 | **看护者自身失护** | 告警腿自己投递失败，时效被兜底周期封顶；哨兵没有 dry-run 开关，一次演练真发了告警；测试只隔离了文件面没隔离网络面 | **谁看护看护者**（告警腿也要有存活与投递成功判据）；哨兵必须有 dry-run；演练必须隔离到测试通道 |

> 十二型覆盖了实证语料中误报的绝大多数成因。新误报先归类再修——**归类错了，修法必错**。

## 四、判据硬化清单（写哨兵时逐条打勾）

- [ ] 时间类断言：`stat` 真实文件，**禁止**用文件名 / 备份名 / 日志名里的时间戳
- [ ] 判据是**纯函数**（给定输入 → 给定输出），可单测，不读写外部状态
- [ ] 首次失败有**复检**（窗口期容忍），复检通过 ⇒ 静默，不留痕不打扰
- [ ] 长期失败的**节奏有阶梯**（如 1/2/5/10/15 分钟），不是固定高频刷屏
- [ ] **自愈成功 = 零输出**；非空输出才投递
- [ ] 同一对象只有**一套判据**（唯一事实源）
- [ ] 判据**窗口感知**：先判"此刻是否应在运行窗口内"
- [ ] 去重键**只在成功路径写**，指纹含具体项与形态
- [ ] 报告带**原始证据原文**（报错 / 退出码 / 端口 / 时间线），不转述
- [ ] 错误分类**不混淆**不同根因（超时 ≠ 限流 ≠ 负载）
- [ ] 有 **dry-run 开关**，演练不打扰真人
- [ ] 有**判定线**：规则上线前的历史残留单独口径
- [ ] **谁看护看护者**：告警腿本身的存活与投递成功有判据
- [ ] 给出**回滚方式**（改坏了怎么退回）

## 五、自证：负控夹具（上线前必过）

任何哨兵上线前必须有**两个**夹具，缺一不算完成：

| 夹具 | 注入 | 期望 |
|---|---|---|
| **正控** | 人工制造该故障 | **必须告警**（不告警 = 哨兵没生效，比误报更危险） |
| **负控** | 保持正常态 / 制造已修复态 | **必须静默**（告警 = 误报） |

- 夹具必须**隔离到测试通道**（文件面 + 网络面都要隔离），否则一次演练就把假告警发给了真人。
- 夹具要能**复跑**（脚本化），并把结果留档；"我手动试过没问题"不算证据。
- ⚠️ 反面教材：哨兵自测只隔离了文件目录、没隔离网络出口，一次干跑把合成告警投进了真实收件箱。

## 六、配套文件

| 文件 | 用途 |
|---|---|
| `references/false-positive-catalog.md` | 十二型详表：每型的实证案例、鉴别方法、修法与回归验证 |
| `scripts/alert_judge.py` | 判据工具箱（纯标准库，含 `--selftest`）：窗口期容忍复检 / 窗口感知调度判定 / 错误分类 / 去重指纹 |

```bash
python3 scripts/alert_judge.py --selftest          # 自测
python3 scripts/alert_judge.py window --cron "*/20 9-21 * * *" --at "2026-09-15T03:10"   # 窗口感知判定
python3 scripts/alert_judge.py classify --msg "connection timed out after 30s"           # 错误分类（不混淆）
python3 scripts/alert_judge.py dedupe --item "disk" --form "usage=97%" --stage success    # 去重指纹
```

## 七、反例（来自真实复盘）

- 告警天天响，用户开始无视 ⇒ 真故障时无人响应（**这是本技能要防的头号事故**）。
- 修完误报不通知被误伤的人 ⇒ 用户仍以为系统不稳。
- 只改阈值不改判据 ⇒ 换个场景又误报（**阈值治症状，判据治根因**）。
- 把误报当"小事"不入档 ⇒ 同一个坑反复踩，无人知道历史上已经踩过。
- 用"最近没报过了"证明修好了 ⇒ 复现不了就是没修好，必须给夹具。

---

**纪律**：误报也是故障（**信任故障**）。定性 → 归类 → 修判据 → 加夹具 → 归档，五步缺一不可；只调阈值不修判据，等于把误报推给下一个场景。
