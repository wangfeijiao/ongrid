# 只读巡检命令清单与阈值表

> 全部命令以只读为原则。工具未安装时跳过该项并标注，不尝试安装。
> 时间基准：先记录系统时间与时区，所有日志时间线判断以服务器本地时间为准。

## 1. 基础信息

| 目标 | 命令 |
| --- | --- |
| 系统版本 | cat /etc/os-release（无则 uname -a） |
| 内核信息 | uname -r |
| 运行时长与负载 | uptime |
| 系统时间与时区 | date；timedatectl（无则 date +"%z"） |
| 硬件核数 | nproc |

## 2. 资源指标

| 目标 | 命令 |
| --- | --- |
| CPU 与负载详情 | top -bn1 | head -20 |
| CPU 队列与 IO 等待 | vmstat 1 5 |
| 内存与 swap（看 available 列） | free -h |
| 磁盘使用率与剩余空间 | df -hT |
| inode 使用率 | df -i |
| 磁盘 IO 延迟（可选） | iostat -x 1 2 |
| TOP5 CPU 进程 | ps aux --sort=-%cpu | head -n 6 |
| TOP5 内存进程 | ps aux --sort=-%mem | head -n 6 |
| D 状态进程（不可中断 IO 等待） | ps -eo pid,stat,wchan:24,comm | awk '$2 ~ /^D/' |
| 僵尸进程 | ps -eo stat,pid,ppid,comm | awk '$1 ~ /^Z/' |

## 3. 网络

| 目标 | 命令 |
| --- | --- |
| 监听端口 | ss -tlnp |
| 连接状态汇总 | ss -s |
| 网卡丢包与错误 | netstat -i |

## 4. 服务与日志

| 目标 | 命令 |
| --- | --- |
| 失败的 systemd 单元 | systemctl --failed |
| 最近错误日志 | journalctl -p err -n 50 --no-pager |
| 内核日志尾部 | dmesg -T | tail -n 20 |
| OOM 记录 | journalctl -k | grep -i -E oom | tail -n 20 |
| 指定时间窗错误日志 | journalctl --since "10 min ago" --until now -p err --no-pager |

## 5. 阈值表（业界基准，双条件取更严格者）

| 指标 | 正常 | 关注 | 危险 |
| --- | --- | --- | --- |
| CPU 使用率（持续 5 分钟以上才判级） | < 70% | 70% - 90% | > 90% |
| CPU iowait（IO 等待占比） | < 10% | 10% - 30% | > 30% |
| CPU steal（虚机被抢占占比） | < 3% | 3% - 10% | > 10% |
| 平均负载 / 核数（看 15 分钟值） | < 0.7 | 0.7 - 1.0 | > 1.5 |
| 内存使用率 | < 80% | 80% - 92% | > 92% |
| 内存 available（剩余可用，优先于使用率） | > 20% | 10% - 20% | < 10% |
| swap 使用率 | < 10% | 10% - 50% | > 50% |
| swap 活动（si/so 持续 > 0） | 无 | 偶发 | 持续出现 |
| 磁盘使用率 | < 80% | 80% - 90% | > 90% |
| 磁盘剩余空间（绝对值，小分区必看） | > 20GB | 10 - 20GB | < 5GB |
| inode 使用率 | < 80% | 80% - 90% | > 90% |
| 磁盘 IO await（SSD 参考） | < 10ms | 10 - 50ms | > 50ms |
| 错误日志密度 | 无 | 偶发 Err | 大量 Err 或 OOM |

判定规则：
- 任一指标进入危险即整体状态为存在风险；多个关注项叠加时升一级。
- 磁盘分区同时看使用率百分比与绝对剩余空间，两者取更严格者。
- 内存判定以 available 为准（used 高但 available 正常多为 page cache，属正常现象）。
- 负载判定看 15 分钟值与趋势：1 分钟值高于 15 分钟值说明负载正在上升，即使绝对值未超线也标记为关注。

## 6. 关联判定（不孤立看单指标）

| 现象组合 | 优先怀疑 | 佐证命令 |
| --- | --- | --- |
| 负载高 + CPU 空闲（us+sy 低） | 磁盘 IO 瓶颈、D 状态进程 | iowait、vmstat b 列、ps 查 D 状态 |
| 内存使用率高 + swap 活动持续 | 内存压力/泄漏 | free available、vmstat si/so |
| CPU steal 持续高 | 物理机资源争用/超卖 | top st 列、联系服务商 |
| 磁盘使用率高 + 服务写失败 | 磁盘满导致写入失败 | df、journalctl -p err |
| 端口不通 + 服务 active | 防火墙或监听地址绑定 | ss -tlnp、iptables -L -n（只读） |

## 7. 常见根因速查（只作方向参考）

| 现象 | 常见根因 |
| --- | --- |
| 负载高但 CPU 空闲 | 磁盘 IO 瓶颈、D 状态进程、内存 swap 抖动 |
| iowait 持续高 | 慢盘、RAID 重建、大文件读写、存储故障 |
| steal 高 | 虚拟化超卖、邻居抢占，需联系服务商 |
| 内存 used 高但 available 正常 | page cache 占位，正常现象不需处理 |
| 内存 available 持续下降 | 内存泄漏、连接数增长、缓存异常 |
| 磁盘将满 | 日志增长、旧备份、容器镜像、核心转储 |
| 服务端口不通 | 服务未启动、防火墙、监听地址绑定错误 |
| 大量 TIME_WAIT | 短连接场景正常，过高时考虑连接复用 |

## 8. 趋势与容量（可选增强）

- 多次巡检对比同一指标（如可用内存每周下降幅度），按增长速率估算触及危险线的时间。
- 负载三值（1/5/15 分钟）同时记录，趋势比单点值更有诊断价值。
- 有 sar 数据时优先参考历史基线，静态阈值只作为起点。
