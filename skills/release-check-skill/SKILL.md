# 上线检查与回滚方案

> 本技能由 zxh 出品，用于 Buddy 应用「Git版本发布助手」。
>
> 所属应用：Git版本发布助手　|　主要工作模式：上线与回滚模式　|　覆盖场景胶囊：上线检查清单、版本回滚说明、迭代会议纪要

## 你会怎么说（触发词）

下面这些说法都会命中本技能，直接用口语提就行：

- 「上线检查清单」
- 「发布前要确认什么」
- 「回滚方案怎么写」
- 「发布流程」
- 「迭代纪要」
- 「上线检查清单怎么搭框架」
- 「有没有上线检查清单的现成模板」
- 「帮我出一版上线检查清单」
- 「帮我列个清单」
- 「做个表格」
- 「有没有核对表」
- 「帮我分析一下」

说法不一样没关系，命中上面任意一条就会路由到本技能。同义说法（如活动方案、策划案、方案模板）也会命中。边界不清楚时，看 frontmatter 的 `description` 里「分工提示」那句。

## 适用场景

- 上线前逐项可勾，回滚有触发条件和可逆性判断。
- 覆盖场景胶囊：上线检查清单、版本回滚说明、迭代会议纪要
- 主要工作模式：上线与回滚模式
- 同应用的其他能力：`git-commit-skill`（提交信息与分支规划）、`release-changelog-skill`（发布说明与版本归档）

## 快速开始（一句话也能跑）

不必先把材料整理好，把手上那句话原样丢过来就行。

| 你可以给的 | 具体 |
|---|---|
| 最小输入 | 「上线检查清单」——有这一句就能起稿 |
| 有就更好 | 版本内容：本次发布范围 |
| 有就更好 | 依赖变更：数据库、配置、第三方、证书 |

缺信息时先按最可能的假设出一版，把假设逐条标成【待确认】，不会停下来干等。

立刻能拿到：上线检查清单；发布步骤表。

## 开始前必须确认（缺项先追问，不自行假设）

| 确认项 | 说明 | 缺失时怎么办 |
|---|---|---|
| 版本内容 | 本次发布范围 | 与 Changelog 对齐 |
| 依赖变更 | 数据库、配置、第三方、证书 | 逐项列变更动作 |
| 灰度与监控 | 发布策略、观察指标、观察窗口 | 未定则给默认建议 |
| 回滚条件 | 什么情况下回滚 | 必须量化（错误率、耗时阈值） |

## 工作流程

1. 产出上线检查清单：代码 / 配置 / 数据 / 依赖 / 权限 / 备份 / 通知
2. 列发布步骤表（步骤 / 执行人 / 预计耗时 / 验证方式）
3. 写回滚方案：触发条件、回滚步骤、数据可逆性说明
4. 定监控观察窗口与关键指标阈值
5. 整理迭代纪要：结论 / 待办 / 风险

## 输出结构

- 上线检查清单（可勾选）
- 发布步骤表
- 回滚方案（含触发条件与可逆性）
- 迭代纪要与监控观察表

完整的输出骨架、填写顺序与逐条打勾表见 @references/output-template.md。

## 交付前自检（红线，逐条打勾）

- [ ] 回滚方案含触发条件与数据可逆性判断
- [ ] 检查项均可勾选、责任到人
- [ ] 不含真实密钥、内网地址与账号
- [ ] 观察窗口与指标阈值明确

## 避坑

- 只写回滚命令不写触发条件，出事没人敢拍板
- 数据不可逆却不在方案里说明
- 检查清单过长过泛，上线时没人真的逐条看

**不适用**：不执行部署、发布与回滚操作。

## 使用案例

### 案例一：一句话直接起稿
- 用户说：上线检查清单
- 需要时会追问：版本内容、依赖变更（没有答复就按假设先跑）
- 拿到：上线检查清单（可勾选）

### 案例二：手上已有材料，帮你梳理成成品
- 用户说：上线检查清单怎么搭框架
- 需要时会追问：版本内容、依赖变更（没有答复就按假设先跑）
- 拿到：发布步骤表

### 案例三：交付前把风险与边界一起兜住
- 用户说：回滚方案怎么写
- 需要时会追问：版本内容、依赖变更（没有答复就按假设先跑）
- 拿到：回滚方案（含触发条件与可逆性）

## 连贯用法

- 出稿 → 归档：用本技能产出后，交给 `workbench-kb-skill` 统一命名并建索引，下次直接复用。
- 同应用串联：`git-commit-skill` → 本技能 → `release-changelog-skill`。
- **成稿落地（文档导出）**：正文定稿后需要落成文件时，**调用下面这几个已在 WorkBuddy 开放平台上架的技能**，不要自己拼装文件格式：
  - 导出 **Word**（`.docx` / `.dotx`）→ 调用 `docx-pro`（Word 文档处理）
  - 导出 **Excel**（`.xlsx`）→ 调用 `xlsx`（Excel 表格处理）
  - 导出 **PPT**（`.pptx` / `.potx`）→ 调用 `pptx`（PPT 演示文稿）
  - 导出 **PDF**（含合并、拆分、加水印、OCR）→ 调用 `pdf-pro`（PDF 文档处理）
  - 用户说「导出 Word」「转成 PDF」「做个表」「做份 PPT」「把这份文档存成文件」等说法时，按上面的对应关系直接转交。
  - **使用前先确认本地已安装**：以上 4 个技能已在 WorkBuddy 开放平台上架，但需本地已安装才能调用；若尚未安装，先通过 WorkBuddy 技能市场按技能名（`docx-pro` / `xlsx` / `pptx` / `pdf-pro`）搜索、安装并启用，再执行导出；**技能未安装时明确提示用户先安装，不要自行拼装文件格式兜底**。
