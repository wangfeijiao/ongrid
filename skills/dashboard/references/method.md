# 看板工坊 · 方法论

## 一、看板布局（ASCII 栅格示例）
```
┌─────────┬─────────┬─────────┬─────────┐
│ KPI 1   │ KPI 2   │ KPI 3   │ KPI 4   │   ← 顶部指标卡片
├─────────┴─────────┴─────────┴─────────┤
│  主图表区（趋势/占比）      │ 次图表区 │   ← 中部图表
├──────────────────────────┬──────────┤
│  明细表 / 列表            │ 告警区   │   ← 底部明细与告警
└──────────────────────────┴──────────┘
```
布局原则：KPI 卡片在上（一眼看关键），主图表在中，明细/告警在下。重要性递减、自上而下。

## 二、刷新机制三档
| 档位 | 技术 | 适用 |
|------|------|------|
| static | HTML + Chart.js 一次性渲染 | 静态汇报 |
| refresh | Streamlit / 定时 fetch + 重绘 | 分钟级监控 |
| realtime | WebSocket + ECharts / Grafana | 秒级实时 |

## 三、三版本方案
- **static**：静态快照，纯前端 HTML+Chart.js，零后端。
- **refresh**：定时轮询（setInterval / Streamlit rerun），标注刷新间隔。
- **realtime**：WebSocket 推送 + 断线重连 + 限流，流式更新。

## 四、五维评分（满分 100）
| 维度 | 权重 | 判定 |
|------|------|------|
| 布局 | 25 | 栅格是否合理、重要度排序 |
| 指标 | 25 | KPI 是否覆盖核心诉求 |
| 刷新 | 20 | 刷新/实时机制是否契合诉求 |
| 交互 | 15 | 筛选/下钻/悬停是否具备 |
| 清晰 | 15 | 标题/单位/图例是否清楚 |
评级：≥85 优秀 / 65–84 良好 / <65 基础。

## 五、本地化要点
段标题、版本名、评分标签、分数单位、优化建议、页脚、署名、摘要行内联标签（指标/刷新/数据源/语言/推荐）全部按语言切换。代码骨架英文注释。

## 六、合规
不接入未授权数据源；凭证走环境变量；实时看板限速+断线重连；敏感指标权限控制；代码骨架仅模板。
