# 智能磁盘清理助手（smart-disk-cleaner）

把磁盘清理做成一条**可复核、可复用、不冒险**的流水线。核心不在"能不能删"，而在于让用户始终知道：**删的是什么、没了会怎样、留着又占多少**。

## 三条铁律（不可协商）

1. **先只读扫描，产出明细，禁止边扫边删。** 任何删除动作必须先出现在用户可见的清单里并获得明确指向（"删/留/迁/清缓存"之一）。不得把用户的批量指令（如"剩下的都删"）当作对未明细项目的授权——**未逐项明细的项目，一律暂停并回问**。
2. **绝不硬删除。** 一律走回收站（Windows `Recycle Bin` / macOS Trash / Linux `gio trash`），不用 `rm -rf`、`Remove-Item -Force` 直删、不用 `del /F`。用户明确要求永久删除时，仍须二次确认。
3. **单任务串行，且必须先确认性能冗余。** 一次只跑一个扫描或删除任务。**更要紧的是：只有在机器存在性能冗余时才允许开始清理——没有冗余就不做，或先降档。** 判据见下节。

## 性能冗余门槛（第零优先级，先于一切）

清理是重 IO + 高内存任务，最坏情况会把用户的电脑拖到卡死。因此**判定标准不是"内存还剩多少"，而是"清理做完之后还能剩多少"**：

```
冗余度 = 清理前可用内存 − 清理过程预估峰值占用(约 1.5 GB)
```

预估峰值 = 脚本自身（0.2 GB）+ 文件系统缓存（0.3 GB）+ 用户已有负载波动（1.0 GB）。

| 冗余度 | 等级 | 动作 |
|---|---|---|
| **> 4 GB** | 充裕 | 可深度扫描，单批 ≤ 10 项 |
| **2–4 GB** | 足够 | 只扫已知清单，单批 ≤ 5 项 |
| **1–2 GB** | 紧张 | 单批 ≤ 3 项、让步翻倍，并告知用户"余量偏紧，我会放慢" |
| **< 1 GB** | **不足** | **拒绝开始清理**。只做只读扫描并建议用户先关闭程序或稍后再来 |

同时必须采集**用户当前负载基线**（内存占用 TOP 进程），识别浏览器 / IDE / 虚拟机 / AI 客户端等重负载程序。冗余偏紧时建议用户先关掉不用的。

`scripts/scan_and_report.ps1` 的 `[PERFORMANCE]` 区块会直接算出 `TIER` 与 `batchMax`；
`scripts/execute_clean.ps1` 在执行前会做冗余门禁（不足则直接拒绝，除非显式传 `-ForceLowMemory`），
并在**每一项开始前重新采样**——冗余掉档就自动降速、跌破 1 GB 立即中止。

完整规则见 `references/04_性能自适应策略.md`。

## 四要素披露标准（强制）

清单里的**每一项**必须回答四个问题，缺一项即视为未完成，用户有权拒答：

| 要素 | 回答什么 | 示例措辞 |
|---|---|---|
| **是什么** | 目录/文件的真实身份、归属哪个应用、里面装的是什么性质的数据 | "这是 npm 的包下载缓存，存放你历次 `npm install` 拉下来的 tgz 压缩包" |
| **有什么用** | 它在系统/应用中的作用，是否是唯一副本 | "作用是离线重装同一版本依赖时免下载；联网环境下可完全重建" |
| **删除的风险** | 分级 + 具体后果 + 是否可逆 | "低风险。后果：下次装同一个包要重新下载；已装好的项目依赖在 `node_modules` 里，不受影响" |
| **不删的影响** | 占多少空间、会不会继续增长、会不会拖慢什么 | "占 3.1 GB，且每次装包持续增长；不删不影响性能，纯占空间" |

风险分级：**低**＝可再生缓存，删了自动重建；**中**＝删后需重装/重配/丢失历史记录但数据另有备份；**高**＝含用户唯一数据或系统运行依赖。

## 工作流（五阶段）

```
P0 性能评估与冗余门禁  →  P1 只读扫描  →  P2 四要素明细 + 规则查表  →  P3 分批执行（含动态复查）  →  P4 结算 + 规则沉淀
```

### P0 性能评估与冗余门禁（必须先做，不过关不许往下走）

在动任何 IO 之前：

1. **采集性能画像** —— CPU 型号/核数、物理内存总量与可用量、磁盘类型（NVMe / SATA SSD / HDD）、当前 CPU 与内存占用率。
2. **计算冗余度** —— 可用内存 − 1.5 GB（清理预估峰值）。这是"能不能开始"的判据，不是"内存还剩多少"。
3. **采集用户负载基线** —— 列出内存占用 TOP 8 进程，识别重负载程序。
4. **定档** —— 按冗余度落入 充裕 / 足够 / 紧张 / 不足 四档，据此决定批次上限与让步频率。

**冗余不足（< 1 GB）时的标准处置**：不做删除，只做只读扫描，并明确告知：

> 当前可用内存 X GB，清理过程预计需要约 1.5 GB 余量。**现在开始有可能导致电脑卡顿甚至卡死。**
> 建议先关闭以下程序再继续：<列出占用最高的几个>。或者我先只做只读扫描（几乎不占资源），
> 把要清理的清单列出来，你等方便时再执行。

把评估结果连同"我会怎么控制节奏"一起告诉用户，让他心里有底。完整规则见 `references/04_性能自适应策略.md`。

### P1 只读扫描

优先调用 `scripts/scan_and_report.ps1`（Windows）。该脚本已实现：进程设为 Idle 优先级、流式枚举不读进内存、分片让出 IO、结果写文件供读取。

扫描目标清单与每项目录含义见 `references/01_目录用途与风险图谱.md`——**这张图谱是本技能的核心资产，禁止凭臆断判断某个目录能否删，一律先查表**。图谱未收录的目录，标记为「未知」并明确告知用户"我不确定这是什么"，不得默认归入可删。

### P2 明细呈现与规则查表

生成清单（HTML 或 Markdown），每项包含四要素 + 当前大小 + 最后使用时间 + 本机实测子目录构成。

然后**查决策规则库**（见下方"规则库机制"）：
- 命中历史规则 → 直接标注"[按你的历史规则：删]"，并在执行确认时一句话带过，不重复展开四要素
- 未命中 → 完整展开四要素，请求用户裁定

### P3 分批执行

按决策分成三批推进，批间清空一次回收站并记录空间：

- **第 1 批 低风险纯缓存**：包管理缓存、浏览器缓存、临时文件、更新残留。删前须扫一遍用户文件特征（如 `.rar`、`.docx`、中文业务文件名），Temp 目录常混有用户自己解压的业务资料，命中即标保留。
- **第 2 批 中风险**：卸载残留、长期未用的工具数据、可再生的 AI/应用数据。这批**必须逐项确认**。
- **第 3 批 迁移或需 GUI/管理员**：聊天工具数据目录迁移、休眠文件、WinSxS 组件清理。提供迁移/操作步骤交给用户，或生成管理员脚本，不强行代劳。

执行约束：单任务串行、每删一项 `Start-Sleep 1~2` 秒、每批 ≤ 配置项数、**批结束必须清空回收站**（否则空间不释放，见 `references/03_执行环境限制与绕行.md`）。

**动态冗余复查（P3 的关键，不可跳过）**：机器负载随时会变——用户可能边清理边新开程序。
因此每一项开始前都要重新采样冗余度与 CPU 负载：

| 复查结果 | 自动动作 |
|---|---|
| 冗余跌破原档次下限 | 降一档（批次上限减半、项间停顿加倍） |
| 冗余跌破 1 GB | **立即中止**，保留已完成部分，如实报告剩余项 |
| CPU 负载持续 > 70% | 项间停顿从 2 秒延长到 5 秒 |
| 用户反馈"卡了" | **立即中止**，不等本批完成 |

降档与中止都要让用户知情。中止时的措辞：

> 检测到可用内存已降至 X GB，为保证电脑不卡，我停在了第 N 项。
> 已释放 Y GB。剩余 Z 项未处理，等你方便时我再继续。

### P4 结算与规则沉淀

输出结算单：前后空间对比、逐项实绩、未完成项及原因、需用户自助的操作清单。

把本轮用户决策写入规则库条目。

## 规则库机制（让第二次清理不用再问）

**存放位置**：`~/.disk-cleaner/decisions.md`（跨会话、跨工作区持久化）。
首次使用时把 `references/02_决策规则库.md` 复制过去初始化：

```bash
cp ~/.workbuddy/skills/smart-disk-cleaner/references/02_决策规则库.md ~/.disk-cleaner/decisions.md
```

**解析契约（重要）**：`scripts/execute_clean.ps1` **只读取 `## 已确认裁定` 小节之后的表格**。
其他小节里的表格（如"出厂默认规则"参考表）一律忽略——这样既能保留一份给人看的默认倾向说明，
又不会让"又写问、又写删"的重复条目污染可执行规则集。**追加新规则请一律写到「已确认裁定」小节内。**

**条目格式**（一行一条，便于 grep 追加）：

```
| 路径模式 | 分类 | 决策 | 依据 | 更新日期 |
|---|---|---|---|---|
| `%LOCALAPPDATA%\npm-cache` | 包管理缓存 | 删 | 可再生缓存 | 2026-09-10 |
```

⚠️ **路径模式列不要写括号说明**。写 `%APPDATA%\Kingsoft（WPS）` 会把"（WPS）"当成路径的一部分
导致匹配失败。说明请写进"依据"列。

**决策取值**：`删` / `留` / `迁` / `清缓存` / `问`。其中：

- `删`、`清缓存` → 命中后**自动执行**，不再询问
- `留` → 命中后静默跳过
- `迁` → 命中后提示迁移路径，不自动执行（迁移需 GUI 操作）
- `问` → 等同于未命中，每次重新走四要素确认

**匹配优先级**：同一路径命中多条时，**模式更长（更具体）的胜出**。
因此"具体路径"天然优先于"通配类别"，可以用一条通配规则定基调、再用具体规则做例外。

**升级处理**：用户对同类项改变决策（如上次要删、这次要留），以**新决策覆盖旧条目**并在依据栏注明变更原因。

**永不自动继承的三类**（每次必问，即使规则库写了也强制跳过）：
1. 用户个人数据目录（Documents / Downloads / Desktop / Pictures / Videos）
2. 含聊天记录、财务、合同、项目底稿的应用数据
3. 风险分级为"高"的任何项

第 1 条在 `execute_clean.ps1` 里以 `$PROTECTED` 硬编码白名单实现，**不可通过配置绕过**。

## 定时自动清理（每 3 天，用户主动启用）

用户可以一次性启用「每 3 天自动清理」，此后无需再手动发起。**启用与否完全由用户决定，本技能绝不默认开启，也不得在用户未明确要求时自行创建任务。**

### 启用条件（三项全满足才可创建）

1. 用户**明确说出**启用意图（如"开启自动清理""每三天帮我清一次""以后自动清"）。
2. `~/.disk-cleaner/decisions.md` **已存在且含 `已确认裁定` 小节** —— 没有规则库就没有自动判定的依据，
   此时先引导用户完成一次完整清理（走 P0→P4）再启用。
3. 用户已明确无人值守的删除边界（见下节）。

### 创建方式

用平台的自动化能力创建**循环任务**（每 3 天一次），任务提示词自包含：

```
使用 smart-disk-cleaner 技能清理本机磁盘。
按"定时自动清理·无人值守协议"执行：低风险项自动删（走回收站，不硬删），
中高风险项只列清单不执行，最后输出简报。
```

| 参数 | 值 |
|---|---|
| 类型 | 循环任务（recurring） |
| 频率 | 每 3 天一次 |
| 提示词 | 上文那段，自包含（不依赖历史对话） |

创建后必须把**任务名与频率**回报给用户，并告知如何暂停/取消。

### 无人值守协议（与交互模式的关键差异）

无人值守时没有用户实时确认，因此**收紧权限，只做低风险自动删除**：

| 项类型 | 无人值守时动作 |
|---|---|
| **低风险**（可再生纯缓存：包管理缓存、浏览器缓存、临时文件、更新残留） | **自动删**（走回收站；每批后清空回收站以真正释放） |
| **中风险**（卸载残留、可再生但需重配的应用数据） | **只列清单，不执行** —— 写入简报等用户下次交互时确认 |
| **高风险 / 三类永不自动继承项** | **强制跳过**，连清单都不列入可删项 |

**额外硬约束（无人值守专属）**：

1. **只走回收站，禁用一切硬删除路径。** 无人值守时不做 `-Force`、不做永久删除，任何情况下都保留可恢复性。
2. **保留 7 天可恢复窗口。** 每批删除后**清空回收站前**，先检查回收站内是否有 **7 天内**的文件：
   若有，**本轮不清空回收站**（只删新项），并在简报里标注"回收站存有近期文件，已保留，待你确认后再释放"。
   这样即使自动判定出错，用户仍有一周时间挽回。
3. **禁止在冗余不足时执行。** 冗余度 < 1 GB 时**只做只读扫描**，简报里说明"本次未清理，因内存余量不足"。
4. **业务文件特征扫描照常执行**（Temp 等目录必扫 `.rar`/`.docx`/中文业务文件名），命中即跳过。
5. **单次总量设上限**（默认 10 GB），超出部分留到下次，避免一次删太狠。

### 简报（每次自动运行时产出）

不管是否真的删了东西，都必须产出简报，内容包括：

- 本次时间、性能冗余等级与档位
- **已自动清理**：逐项 + 大小 + 释放总量
- **待你确认**：中风险项清单（含四要素摘要）
- **已跳过**：命中的保护项及原因
- **未执行原因**（若冗余不足或本轮无新项）
- 规则库变更（本次新增/覆盖了哪些裁定）

简报应当推送到用户可见的地方；若平台不支持主动推送，则写入固定路径（默认
`~/.disk-cleaner/last_auto_run.md`）并提示用户下次打开时查看。

### 暂停与取消

用户说"关掉自动清理""暂停定时任务"时，**立即删除或暂停对应循环任务**并回报结果。
不得以"保留备用"为由留下用户已要求取消的任务。

## 脚本用法

### 扫描（P1）

```powershell
# 浅扫：只扫已知目标清单
powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts/scan_and_report.ps1 -Drive C -OutFile .\disk_scan_report.txt

# 深扫：额外遍历 AppData\Local 与 Roaming 的每个一级子目录
powershell -NoProfile -ExecutionPolicy Bypass `
  -File scripts/scan_and_report.ps1 -Drive C -Deep -MinSizeMB 200
```

输出为结构化文本，含五个区块：`[PARTITION]` 分区概况、`[PERFORMANCE]` 性能画像与节奏建议、
`[CANDIDATES]` 候选目录、`[SYSTEM]` 系统级专项、`[RECYCLEBIN]` 回收站、`[TEMP-WARNING]` 业务文件预警。

### 执行（P3）

```powershell
# 先预演（默认模式，不做任何修改）—— 推荐每次清理都先跑这个
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/execute_clean.ps1

# 确认无误后真正执行
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/execute_clean.ps1 -Execute -BatchMax 5

# 也可脱离规则库，按临时清单执行
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/execute_clean.ps1 `
  -Paths "$env:LOCALAPPDATA\npm-cache","$env:LOCALAPPDATA\pip" -Execute -PurgeRecycleBin
```

`-Execute` 是必须开关。不加则永远是 DRY-RUN。日志中每项会标注 `WILL_DELETE` / `NEED_CONFIRM` / `SKIP`，
**`NEED_CONFIRM` 的项必须回到对话层向用户完整披露四要素后才可处理**。

### 无人值守执行（定时任务专用）

定时任务调用时**必须**加 `-AutoMode`，权限会自动收紧（见"定时自动清理"章节）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/execute_clean.ps1 `
  -AutoMode -Execute -BatchMax 5 `
  -OutFile "$env:USERPROFILE\.disk-cleaner\last_auto_run.txt"
```

AutoMode 下日志会多出 `[AUTO-MODE GUARD]` 段，含四项守卫的实际判定：

| 日志行 | 含义 |
|---|---|
| `RB-GUARD\|…` | 回收站是否有 7 天内文件（有则本轮不清空） |
| `SCOPE\|低风险可执行 N 项；中/高风险降级 M 项` | 筛选结果 |
| `HELD\|<名称>\|[<分类>]` | 被降级、未执行的项 |
| `CAP\|单次释放上限 XGB` | 单次总量上限 |

**建议先用 DRY-RUN 验一遍再交给定时任务**：`-AutoMode` 不带 `-Execute` 即可预览
"哪些会被自动删、哪些被降级"，这是上线前最有价值的自检。

### 管理员项目（P3 交付用户）

```bat
:: 右键 → 以管理员身份运行
scripts\admin_cleanup.bat
```

脚本逐项交互式询问（休眠 / Windows 更新缓存 / DISM 组件清理 / 厂商残留 / OneDrive），
每项都可跳过，全程 `pause` 让用户看清结果。

## 环境适配说明

本技能在 **Windows** 上提供了完整可执行脚本（PowerShell + bat）。在 **macOS / Linux** 上，
流程与方法论同样适用，但需将脚本中的等价命令替换：

| 操作 | Windows | macOS | Linux |
|---|---|---|---|
| 进程降级 | `[System.Diagnostics.Process]` PriorityClass=Idle | `renice +20 -p $$` | `renice +20 -p $$` |
| 流式枚举 | `[System.IO.Directory]::EnumerateFiles` | `find <dir> -type f -printf '%s\n'` | 同 macOS |
| 删除到回收站 | `Remove-Item` / Shell.Application | `trash <path>` | `gio trash <path>` |
| 清空回收站 | `Clear-RecycleBin` | `rm -rf ~/.Trash/*` | `gio trash --empty` |
| 查可用空间 | `Get-CimInstance Win32_LogicalDisk` | `df -h /` | `df -h /` |

`references/01` 与 `references/04` 是跨平台通用的；`references/03` 为 Windows 专属经验。

## 首次使用检查清单

调用本技能时按序自检，任一项未满足则先补齐：

1. **任务类型判定** —— 是"首次清理（走四要素全流程）"还是"按规则复用（直接进 P3）"？
   判据：`~/.disk-cleaner/decisions.md` 是否存在且含 `已确认裁定` 小节。不存在 → 首次清理。
2. **规则库初始化** —— 不存在时复制模板过去，然后从 P0 开始走全流程。
3. **性能画像** —— 必须实测，不可跳过。可用内存决定后面能走多深（见 `references/04`）。
4. **单任务确认** —— 确认当前没有其他扫描/删除任务在跑。
5. **脚本可执行性** —— PowerShell 脚本必须带 UTF-8 BOM，否则 Windows PowerShell 5.1
   会按本地代码页解析中文而报语法错误。可用以下命令补 BOM：
   ```powershell
   $p = 'scripts\scan_and_report.ps1'
   $c = [System.IO.File]::ReadAllText($p)
   [System.IO.File]::WriteAllText($p, $c, (New-Object System.Text.UTF8Encoding $true))
   ```
   ⚠️ **反向约束**：`SKILL.md` 本身**必须无 BOM**，且含 `:` 的 frontmatter 值必须加双引号，
   否则平台上传报「frontmatter 无法解析」（详见 `references/03` 坑 14）。二者要求相反，勿一刀切。
