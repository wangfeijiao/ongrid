# 决策规则库（默认模板）

> **本文件是模板。** 运行时的真实规则库存放在 **`~/.disk-cleaner/decisions.md`**。
> 首次使用本技能时：若目标文件不存在，把本模板复制过去，然后按实际用户决策追加/覆盖条目。
> 修改规则文件的唯一入口：用户对某一项做出明确裁定之后。禁止自动推断生成规则。

## 文件格式

一行一条 Markdown 表格行，便于追加和 grep：

```
| 路径模式 | 分类 | 决策 | 依据 | 更新日期 |
|---|---|---|---|---|
| `%LOCALAPPDATA%\npm-cache` | 包管理缓存 | 删 | 可再生，重装有网即可 | 2026-09-10 |
```

**决策取值**：`删` / `留` / `迁`（迁移到数据盘）/ `清缓存`（只清可再生子目录，保留运行环境）/ `问`（每次必问）

**解析规则（脚本据此读取）**：

- 只有 `## 已确认裁定` 小节**之后**的表格行才会被脚本读取。写在其他小节的表格一律忽略。
- 路径模式可含 `%LOCALAPPDATA%`、`%APPDATA%`、`%TEMP%`、`%PROGRAMDATA%`、`%USERPROFILE%` 环境变量。
- 支持 `*` 通配。同一路径命中多条规则时，**模式更长（更具体）的胜出**，因此"具体路径"天然优先于"通配类别"。
- 决策写 `问` 的条目等同于未命中，会进入待确认清单。
- 路径模式后面**不要**写括号说明 —— 会被当作模式的一部分导致匹配失败，说明请写进"依据"列。

## 出厂默认规则（参考用，脚本不读取）

> ⚠️ 下面这张表**只是给人看的参考**，用于说明"尚未获得用户裁定时应当询问"。
> 脚本不解析本节。真正的可执行规则必须写在文末的 `## 已确认裁定` 小节里。

| 路径模式 | 分类 | 默认倾向 | 说明 |
|---|---|---|---|
| `%LOCALAPPDATA%\npm-cache` | 包管理缓存 | 倾向删 | 确认用户在用 npm 后即可定 |
| `%LOCALAPPDATA%\pip` | 包管理缓存 | 倾向删 | 同上 |
| `%LOCALAPPDATA%\pnpm-cache` | 包管理缓存 | 倾向删 | 同上 |
| `%LOCALAPPDATA%\go-build` | 构建缓存 | 倾向删 | 同上 |
| `%LOCALAPPDATA%\Microsoft\Windows\INetCache` | 浏览器缓存 | 倾向删 | 可再生 |
| `%TEMP%` | 临时文件 | **必问** | 常混有解压的业务资料，必须先扫 |
| `%LOCALAPPDATA%\CrashDumps` | 崩溃转储 | 倾向删 | 正在排查崩溃时才有价值 |
| `C:\hiberfil.sys` | 系统休眠 | **必问** | 关快速启动会影响开机速度 |
| `C:\Windows\WinSxS` | 系统组件存储 | **必问** | 只能 Dism 官方清理，禁止手动删 |

## 永不自动继承规则的高敏类别

以下类别**不允许写入固定规则**，每次必须回到四要素确认流程：

1. 用户个人库：`Documents` / `Downloads` / `Desktop` / `Pictures` / `Videos` / `Music`
2. 聊天与通讯数据：微信 / QQ / 钉钉 / 飞书 的聊天记录、图片视频收件夹
3. 财务与法务：合同、财报、发票、工商变更材料、税费申报
4. 项目工作底稿：任何含 `.xlsx` / `.docx` / `.pdf` / `.dwg` / `.psd` 的自定义目录
5. 应用安装目录本身（`Program Files` / `AppData\Local\Programs` 下的已安装程序）

## 规则冲突与覆盖

- 同一路径模式出现新旧两条决策 → **以更新日期最新者为准**，并在依据栏注明「变更原因：……」
- 用户对同一分类下的**某个具体路径**给了不同决策 → 保留两条，具体路径优先于通配模式（更具体的规则胜出）
- 用户表达「以后这类都别问我了」→ 把该分类下所有**已明细且风险为低/中**的条目批量转为对应决策，高敏类别除外
