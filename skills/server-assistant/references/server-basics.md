# 服务器入门总览

这篇解决三件事：**第一小时该干什么**、**买配置/选系统怎么选**、**为什么端口明明开了还是连不上**。
`203.0.113.10` 是文档保留地址，真实环境替换成你自己的公网 IP（云控制台实例详情页可见）。
先通读这篇，再按任务跳到 `server-init.md`（初始化）或 `ssh-login.md`（连不上）。

## 一、新手第一小时：固定动作顺序

刚拿到一台新机器，**顺序错了会把自己锁在门外**。按这个顺序做：

```bash
# 1) 先开一个「保底窗口」：云控制台的网页终端 / VNC，保持开着别关
#    这样即使 SSH 配错、防火墙配错，你还有一条路能进服务器

# 2) 确认系统版本（第一次必做，后面所有命令都依赖它）
# ✅ 只读
cat /etc/os-release

# 3) 立刻改 root 密码
# ⚠️ 有副作用：会踢掉当前会话，重新登录即可
passwd root
```

```bash
# 4) 建一个自己的用户并给 sudo 权限
# ⚠️ 有副作用：adduser 会创建 home 目录和同名用户组
adduser deploy              # Ubuntu / Debian / Rocker/AlmaLinux 都有
# ⚠️ 有副作用
usermod -aG sudo deploy     # Ubuntu / Debian 用 sudo 组
usermod -aG wheel deploy    # CentOS / Rocky / AlmaLinux 用 wheel 组

# 5) 先别急着关密码登录，此时自己也登一次，确认新用户能进
# ✅ 只读：从你自己电脑上验证
ssh deploy@203.0.113.10
```

```bash
# 6) 配置你的 SSH 公钥（见 @ssh-login.md 的完整步骤）
#    公钥放上去、免密能登，这一步做完后才考虑禁密码

# 7) 最后做系统更新和防火墙（见 @server-init.md）
apt update && apt upgrade -y    # Ubuntu / Debian
# 或
dnf update -y                   # Rocky / AlmaLinux / CentOS Stream
# 或
yum update -y                   # CentOS 7（已 EOL，见下文）
```

**为什么是这个顺序**：改密码 → 建用户 → 配密钥 → 最后才关密码登录。反过来做（比如先禁密码，密钥还没配好）就会把自己关在门外。
**坑点**：`usermod -aG` 少了 `-a` 会把用户从其他所有附加组里踢出去，`deploy` 可能突然没有 `sudo`/`docker` 等权限。详见 `server-init.md`。

## 二、云主机配置怎么选

按「轻量应用」思路选，够用即可，后期升配比前期选高便宜：

| 项目 | 建议 | 理由 |
|---|---|---|
| CPU/内存 | 小型官网、博客、后台：1核2G；有数据库+应用：2核4G | 内存比 CPU 更容易成为瓶颈，MySQL/Java 都是吃内存的 |
| 系统盘 | 40~60 GB SSD | 系统本身只占几个 G，主要留出日志和临时文件空间 |
| 数据盘 | 需要放数据库文件、备份、大附件时再买 | 独立盘可以单独做快照、单独扩容，不拖累系统盘 |
| 带宽 | 国内固定 1~5 Mbps；纯 API/内网服务可以 1 Mbps | 国内带宽单价高，静态站可以配 CDN 分担 |
| 型号 | 轻量应用服务器 / 通用型 g 系列足够 | 计算型 c 系列、内存型 r 系列只在特定负载下才划算 |

**为什么**：分系统盘/数据盘的差别在于「重装时数据在哪」：数据库放数据盘，重装只格式化系统盘，数据盘挂回去就还在。
**坑点**：买了数据盘不会自动挂载，`df -h` 看不到就是没挂上，要手动 `mkfs.ext4 /dev/vdb && mount` 并写进 `/etc/fstab`。具体机型名与计费规则**以当前平台控制台为准**。

## 三、发行版怎么选

| 发行版 | 适合谁 | 包管理器 | 需要注意 |
|---|---|---|---|
| Ubuntu 22.04 LTS / 24.04 LTS | 新手首选，文档最多，云镜像最全 | `apt` | 半年一升级，5 年支持 |
| Debian 12 (bookworm) | 追求稳定、不喜欢被新版本追着跑 | `apt` | 软件版本偏旧，有时装不上最新的 Node/Python |
| Rocky Linux 9 / AlmaLinux 9 | 原来用 CentOS 的人，兼容 RHEL 生态 | `dnf` | 注意 CentOS 与 Rocky/Alma 的命名混乱，别装错 |
| CentOS Stream 9/10 | RHEL 的上游开发版，想跟 RHEL 同步 | `dnf` | **它不是稳定版**，会滚动更新，生产环境要评估 |
| CentOS 7 | 不建议，已 EOL | `yum` | 停止安全更新，公网机器风险实打实 |

**为什么**：选发行版就是选「遇到问题能搜到多少答案 + 有没有安全更新」，Ubuntu 中文资料量最大、`apt` 行为最可预测。
**坑点**：
- EOL（End of Life）版本不再收安全补丁，被扫描被提权的概率明显更高，日期以**各发行版官方 EOL 表**为准。
- 镜像源配错版本会让 `apt update` 报 404 或 GPG 错误，最常见是把 20.04 的源用在了 22.04 上。
- 不确定版本先跑 `cat /etc/os-release`，把输出贴出来再决定。

## 四、登录方式对比

| 方式 | 用途 | 什么时候用 |
|---|---|---|
| 云控制台 VNC / 网页终端 | 不依赖网络的「救援通道」 | SSH 连不上、改错了配置、忘了密码时的最后手段 |
| SSH 密码登录 | 临时上机、第一次登录 | 刚买的机器、应急排障 |
| SSH 密钥登录 | **日常主力方式** | 所有常规操作，尤其是要频繁登录时 |

```bash
# ✅ 只读：测试网络通不通（在你自己电脑上跑，不是服务器上）
ping -c 3 203.0.113.10
```

**为什么推荐密钥**：密码登录会被全网扫描机器人暴力破解，公网上 22 端口几分钟内就收到尝试记录；密钥几乎猜不到。
**坑点**：网页终端剪贴板与本地不完全一致，多行命令粘进去可能出错，长脚本先存成本地文件再传（见 `file-transfer.md`）。macOS「终端」、Windows 11「终端 / PowerShell」自带 OpenSSH，老版本 Windows 需另装 OpenSSH 或用 WSL，详见 `ssh-login.md`，以当前系统版本为准。

## 五、安全组 vs 系统防火墙（最大的认知盲区）

**这两层是独立的，互不影响，必须两层都放行端口才能通。** 云厂商的「安全组」在云侧拦包，服务器里的 `ufw` / `firewalld` / `iptables` 在系统侧拦包。

```
你的电脑 ──► 云安全组（云机房）──► 系统防火墙（服务器里）──► 服务进程
             必须放行 22/80/443     必须 allow 相应端口       必须真的在监听
```

三条现象对照：

| 现象 | 最可能的原因 |
|---|---|
| `ping` 都不通、SSH 超时 | 安全组没放行 22，或实例已关机 |
| 连接直接被拒（Connection refused） | 安全组通了，但 `sshd` 没在 22 上监听 |
| 网站打不开，但能 SSH 进去 | **防火墙没放行 80/443，或进程没监听，或安全组没放行** |

```bash
# ✅ 只读：看系统侧防火墙拦什么（Ubuntu/Debian）
ufw status numbered
# ✅ 只读：看进程有没有真的在监听 80 / 443 / 3306
ss -tulnp | grep -E ':80|:443|:3306'
# ✅ 只读：在服务器本机自测服务本身（不走网络栈，可排除防火墙干扰）
curl -I http://127.0.0.1
```

```bash
# ⚠️ 有副作用：放行 SSH / HTTP / HTTPS（Ubuntu/Debian）
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp
# ⚠️ 有副作用：重新加载规则
ufw reload
# ✅ 只读：CentOS/Rocky/AlmaLinux 对应查看
firewall-cmd --list-all
# ⚠️ 有副作用：放行 80 端口
firewall-cmd --permanent --add-port=80/tcp && firewall-cmd --reload
```

**为什么**：只在服务器里配了防火墙就以为万事大吉，结果云侧安全组把包丢了，现象和「防火墙没配」一模一样；反过来只开安全组、忘配 `ufw`（默认 deny），一样连不上。
**坑点**：
- 22 端口建议改成非标准端口再放行，能少挨很多扫描（见 `server-security.md`）。
- 数据库（3306/6379/27017）不要对公网放行，只放行你的出口 IP；必须外网访问就加 IP 白名单。
- 平台菜单名与字段名会改版，**以当前控制台为准**；命令对照表见 `server-init.md`。

## 六、快照与镜像

| | 快照 snapshot | 镜像 image |
|---|---|---|
| 本质 | 某时刻**磁盘数据**的备份 | 一台**整机**模板（系统盘+数据盘+配置） |
| 用途 | 回滚误删、定时备份 | 批量开同配置机器、迁移、灾备 |
| 回滚 | 用快照重建云盘 | 用镜像开新实例，老机器数据需另备 |

**为什么**：`rm -rf` 删错东西时快照是唯一能救回来的东西（除非你有备份脚本），定时快照比人肉记得备份靠谱得多。
**坑点**：快照**不等于备份**，「服务器上删了文件、之后生成的快照」同样没有那个文件。正确组合是「定时快照 + 异地备份」，见 `backup-restore.md`。快照按量计费，策略设成每天一次、保留 7 天就够，别设保留 3 年。

## 七、花钱省事的建议

1. **不需要就停机**：临时机器用完到控制台「停止」实例，包年包月实例停机后计算资源不计费（**以平台控制台为准**）。
2. **能用镜像就别重复装**：第一台调好的环境固化成「自定义镜像」，下次直接开，省掉全部初始化时间。
3. **静态资源交给 CDN**：图片/JS/CSS 放对象存储 + CDN，比升级带宽便宜得多。
4. **初始化写成脚本**：第二、三台机器的第一件事就是复用第一台的手工步骤——这也是三条铁律的第三条。
