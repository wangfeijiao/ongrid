# 通用方法论（PC 自动化技能家族共用）

本文件是「电脑自动化顾问 / 方案生成器 / Excel 顾问 / 审计师」等一系列技能的**共用方法论**。
各技能在 `SKILL.md` 中通过 `详见 references/methodology.md` 引用本文件，打包时由 `sync.py` 复制到各技能目录下，实现「开发时共享、上传时各自包含」。

---

## 1. 精准三原则

- **有证据**：每条建议必须对应一条真实观察到的信号（如"下载目录检测到 47 个 img_ 批量序号文件""每周三固定出现 12 个同前缀 xlsx"）。无证据的只进"待确认"，不凑数。
- **可量化**：必须算出"每月省多少小时"= 频率 × 单次耗时，用用户给的真实数字，不让 AI 瞎估。
- **经校准**：机器看客观信号（频率/堆积/周期），用户看主观痛点（烦不烦），两者加权才排得准。纯扫描只能给"可能相关"，加上校准才是"你最该甩出去的那几件"。

## 2. 只读盘点（不读文件内容、不改不删）

扫描范围与信号：
- 常驻进程 / 已装软件（推断工作类别）
- 目标目录一层的**扩展名分布**、**批量序号文件**（同前缀 ≥3 → 该批量重命名/归档）、**格式混放**（docx 与 pdf 同目录 → 该统一/转换）
- 最近文件的**星期周期性**（看出是否每周固定干某件）
- 计划任务（周期性动作）、效率工具缺口（重复点同一串手动操作）

> 配套脚本 `scripts/lightweight_inventory.ps1` 即为只读盘点实现（Windows PowerShell）。脚本只统计文件名称/大小/类型，**绝不打开文档图片内容，也不动任何文件**。

## 3. 评估与排序（证据 E × ROI R × 痛点 P）

| 维度 | 刻度 |
|---|---|
| 证据强度 E | 3 强 / 2 中 / 1 弱（对应上述信号的确凿程度） |
| ROI R | 3 高（月省 ≥4h）/ 2 中（1–4h）/ 1 低（<1h） |
| 痛点分 P | 1–5（由用户校准，5 = 最想甩手） |

综合分 = E × R × P。

档位切分：
- **P0 立即做**：综合分靠前 **且** 月省时 ≥ 2 小时，最多 5 条（你最烦 + 证据确凿 + 真省时间，三者齐了才"现在就干"）
- **P1 计划做**：未全满足 P0 但值得做（收益中 1–4h，或痛点中 2–3），排进待办
- **P2 / 不优先**：月省 < 1h 且 痛点低（1–2），基本不推荐，列进"没推什么 & 为什么"

## 4. 痛点校准闭环（精准的核心）

1. 初稿：基于只读盘点列出候选 + 证据 + 推断月省时，先不排序。
2. 校准：逐项问用户——频率/耗时对不对？这事打几分烦（1–5）？漏了什么更烦的？
3. 重排：用户打完分后用「证据 E × ROI R × 痛点 P」重排，输出 Top N。

> 关键认知：机器初判会被强信号带偏（例如"微信常驻 + 今天收 5 张图"看似该推 IM 收图整理，但用户真实痛点分可能只有 3）。**未经校准的纯扫描会误推**，校准闭环是精准的必要环节。

## 5. 落地安全铁律

- 默认**只读 / 新建**，不删不移动任何文件。
- 方案若含移动 / 删除 / 归档：必须逐项目单独**二次确认**，且走回收站（不 `rm` / `del /F`）。
- 敏感文件（照片 / 隐私素材）：默认**本地离线处理，绝不上外网**；涉及外部账号 / API Key 由用户自行保管，不在对话里明文收集。
- 依赖安装隔离到受管 venv，不污染用户环境。
- 交付 `.ps1` 脚本**必须带 UTF-8 BOM**（或纯 ASCII），否则中文 Windows 的 PowerShell 按 GBK 读会乱码报错（真实会踩的坑）。
- 涉及外部系统 / 企业内网的自动化，提示用户自担风险并保管凭据。

## 6. 先查已有工具（避免重复造轮子）

建议新建工具 / 脚本前，先确认用户是否**已有同类工具或脚本**（口头问 / 查工作目录 · Recent · 下载）。已有则改推「复用 / 加固现有」而非从零新建。

## 7. 平台说明

- 配套盘点脚本是 Windows PowerShell；macOS / Linux 用等价只读命令（`ls` 顶层目录、`ps` / `crontab -l`）即可，诊断流程不受影响。
- 各技能上传市场时须自带 frontmatter：`version` / `display_name` / `display_name_en` / `description_zh` / `description_en`。
