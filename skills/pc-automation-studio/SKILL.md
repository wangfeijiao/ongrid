# 电脑自动化全流程助手（pc-automation-studio）

## Overview
本技能是「电脑自动化顾问」的合并增强版：**既诊断，也落地**。它先基于电脑上真实可见的信号、结合用户本人校准的痛点，找出"最该、最划算、最该先甩给 AI"的那几件工作（第一阶段·精准诊断）；用户从中选定一项后，再生成一份可落地的实施方案，经用户确认后，直接把工具/脚本/定时任务建好（第二阶段·方案与落地）。

**精准三原则**（第一阶段贯穿，不满足就不列为建议）：
1. **有证据**：每条建议必须对应一条在盘点中真实观察到的信号（进程 / 文件堆积 / 批量序号 / 格式混放 / 周期 / 计划任务），禁止凭空猜测"你大概会需要"。
2. **可量化**：必须能算出"每月大约省多少时间"（频率 × 单次耗时），用用户给的真实数字，不让 AI 拍脑袋。
3. **经校准**：痛点分由用户用 1–5 打分确认；机器看频率，人看烦不烦，两者加权才算准。

**落地总铁律（第二阶段核心）**：生成方案可以主动，但**执行前必须用户明确确认**；默认只读/新建、不删不移动；任何动文件的动作都要单独二次确认。

## 首次引导（打开技能即触发，降低新用户门槛）

用户第一次触发本技能时，**不要直接甩长篇流程**。按下面三步轻量引导，用户只做选择题：

1. **打招呼 + 一句话定位**："我是电脑自动化全流程助手——先帮你找出最该交给 AI/脚本的重复活，确认后我还能直接帮你做出来（工具/脚本/定时任务）。"
2. **问范围（二选一或组合，摆出来让用户回一个字母/一句话即可）**：
   - **A. 全面盘点**：按默认安全范围只读扫描（桌面/下载/文档/进程/计划任务）。
   - **B. 聚焦某类**：办公文档 / 文件整理 / 数据报表 / 内容运营 / 开发运维 / 重复点击(RPA)。
3. **给一条最短路径**："你回'全面盘点'，我就只读扫一遍、给你 Top N 最该自动化的活；你挑一件说'做掉第 3 件'，我生成方案、你确认后直接落地。"

引导阶段**只读、不扫描、不写任何文件**；用户没回范围之前，不进入第一阶段第 1 步。新用户无需读文档，回一两句就上手。

## 与「电脑自动化顾问」系列的关系（分工明确，不抢活）

本技能是「落地执行器」，不是又一个诊断顾问。三者定位：

- **电脑自动化顾问（skill · 轻量快诊 / PC Automation Quick Scan）**：快速扫描、给 Top N 建议，**不落地**。适合"我就想先看看哪些活能自动化"。
- **电脑自动化顾问（专家版 · automation-consultant-expert）**：深度诊断 + 进度记忆 + 方案落地追踪 + 换机对比，诊断与持续跟踪为主，落地偏方案层。
- **电脑自动化全流程助手（本技能 · pc-automation-studio）**：**接住前两者给出的"第 X 件"，生成可落地方案并真正建好工具/脚本/定时任务**。

**协作姿势**：顾问诊断完说"把第 3 件做掉 / 生成方案落地"，即把那一项交给本技能执行——本技能是第一、二阶段的"执行器"。诊断归顾问，落地归 studio，互不抢活，流量自然分流。

## 何时使用
- 用户想知道"我的哪些重复工作能自动化"
- 用户觉得"每天在电脑前做很多机械事，想让 AI 帮着干"
- 用户请"盘点一下我的电脑使用习惯，给提效建议"
- 用户想了解"本平台 / AI 能替我干哪些活"
- 用户在拿到推荐后说"把第 X 件做掉""生成方案""落地""做成工具/脚本让我用"

# 第一阶段：诊断 · 精准推荐

## 工作流程

### 第 0 步：界定范围，先取得同意（必须）
不要一上来就全盘扫描。先用一两句话向用户确认聚焦方向，二选一或组合：
1. **全面盘点**：按默认安全范围扫描（见第 1 步）。
2. **聚焦某一类工作**：如"办公文档处理""文件整理""数据报表""内容运营""开发运维""重复点击流程（RPA 类）"。

同时明确告知：盘点**只读、不修改、不删除任何文件**，且不会深入读取个人文件内容。若用户只想口头讨论思路、暂不扫描，直接进入第 2~5 步，基于用户自述的使用习惯给建议即可（但第 2.5 步的 ROI 仍要向用户追问真实数字）。

### 第 1 步：轻量盘点（只读收集）
优先调用 `scripts/lightweight_inventory.ps1`（安全只读，额外输出更精准的信号：批量序号文件、文档格式混放、最近文件星期分布（周期性）、效率工具缺口、进程疑似工作类别）。默认扫描以下位置**仅一层**（不递归深层个人目录）：
- 桌面、下载、文档、当前工作区
- 最近使用过的文件（Recent 列表）
- 当前运行的进程 / 常驻软件（带疑似工作类别）
- 计划任务（定时在跑的东西）
- PATH 中常见的 CLI / 开发工具是否安装
- 指定目录下的文件**类型分布**与**模式信号**统计（按扩展名计数、批量序号检测、格式混放检测，不读内容）

用法示例：
```powershell
powershell -ExecutionPolicy Bypass -File "~/.本平台/skills/pc-automation-studio/scripts/lightweight_inventory.ps1" -ScanPaths "桌面路径","下载路径","工作区路径"
```
也可只让用户口述，或让 本平台 用少量等价只读命令（如 `Get-Process`、`ls` 顶层）临时收集，避免任何敏感目录深层访问。

**安全红线（严格遵守）**：
- 只读、不改、不删；不读取文档 / 图片 / 表格的内部内容。
- 不递归 Desktop / Downloads / Documents / Home 的子目录深层（最多一层）。
- 不扫描凭据、密钥、浏览器密码等敏感文件。
- 任何"要动文件"的后续动作，必须再次单独征得用户确认（见第二阶段与 personal_files_safety 规则）。

### 第 2 步：识别可自动化候选（带证据门槛）
把第 1 步信号对照 `references/automation-catalog.md` 的"精准触发信号"逐条映射。**硬规则**：每条候选必须能指出一条具体证据（如"下载目录检测到 47 个 img_ 开头的批量序号文件""每周三固定出现 12 个 xlsx 导出""进程同时常驻浏览器 + Excel"）。
- **有证据** → 进入候选池，记录"证据原文"。
- **无证据、只是听起来相关** → 放入"待确认观察项"，**不要**直接列为建议；可追问用户是否属实。
- **先查已有工具（避免重复造轮子）**：在把某条候选标注为"建议新建工具/脚本"之前，先确认用户是否**已有同类工具或脚本**——可口头询问，或在常见工作目录 / Recent / 下载中查找同类文件（如用户自己攒的离线 HTML 小工具、Python/PowerShell 脚本）。若用户已有可满足需求的工具，则改为"复用 / 加固现有"而非从零新建；这条对图片处理、PDF 工具、媒体转换等用户常自己攒小工具的场景尤其重要。

### 第 2.5 步：量化 ROI（用真实数字，不猜）
对候选池每条，向用户确认两个真实数字（若盘点已能推断频率，先给出推断值请用户修正）：
- **频率**：每周几次 / 每月几次
- **单次耗时**：分钟
计算 **月省时 = 频率(月) × 单次耗时**。设阈值：
- 月省时 ≥ 4 小时 → 高收益
- 1–4 小时 → 中收益
- < 1 小时 → 低收益（除非痛点极高，否则不进 P0）

### 第 3 步：评分与排优先级（证据 × ROI × 痛点）
三维打分，综合成优先级：
- **证据强度**：强（有直接信号）/ 中（间接信号）/ 弱（仅用户口述）
- **ROI**：按第 2.5 步 高(3) / 中(2) / 低(1)
- **痛点分**：请用户对每条候选评 1–5（"这事你有多烦 / 多想甩手"）

**排序分 = 证据强度(3/2/1) × ROI(3/2/1) × 痛点分(1–5)**，按乘积降序。

优先级（基于排序分）：
- **P0（立即做）**：排序分靠前且月省时 ≥ 2 小时，聚焦 **最多 5 条**。
- **P1（计划做）**：中收益或痛点中等。
- **P2（以后看）**：低收益且痛点低。

### 校准闭环（关键，决定"准"不准）
输出初稿 Top 候选（含推断的频率 / 耗时 + 痛点待打分）给用户，**逐项请用户确认 / 修正**：
1. 这事的真实频率、单次耗时对不对？
2. 痛点打几分（1–5）？
3. 有没有我们漏掉、你更烦的活？
依据回复重排，再给终稿。这一步不能省——没有校准的清单只是"可能"，校准后才是"精准"。

### 第 4 步：给出方案与思路（绑定证据与 ROI）
对每条 P0 / P1 候选，产出一页式方案，包含：
1. **自动化目标**：一句话说清"代替人做什么"
2. **证据**：引用的具体信号（来自第 2 步）
3. **推荐落地方式**（选最合适的一种或组合）：
   - 直接让 本平台 现做（一次性任务）
   - **复用 / 加固用户已有工具**（若第 2 步发现用户已有同类工具，优先此方式，不重复新建）
   - 沉淀成一个 **本平台 技能（Skill）** 复用
   - 写一段 **脚本**（Python / PowerShell）定时跑
   - 创建 **定时自动化**（automation_update，recurring / once）
   - 接入 **连接器 / MCP**（如需要外部系统数据）
   - 用现成工具（如 Power Automate、浏览器插件）兜底
4. **关键步骤草图**：3–5 步，点到为止
5. **预计月省时**：来自第 2.5 步的真实数字
6. **注意点 / 风险**：数据隐私、需用户确认的删除动作、外部依赖

输出语言通俗，避免术语堆砌；方案要"用户拿去就能开工"，不是泛泛而谈。

### 第 5 步：输出建议清单（聚焦 + 排除项）
用一张结构化表格汇总，列：候选工作 | 证据 | 月省时 | 痛点分 | 优先级 | 推荐方式 | 下一步。要求：
- **P0 不超过 5 条**，宁少勿泛。
- 表格后必附"**这次没推荐的事 & 为什么**"（如：某活虽能自动化但月省 <1h、或需人工判断、或涉及隐私不便），提升可信度 = 精准感。
- 附"建议先做的 3 件事"。

> 第一阶段到此输出推荐清单。若用户说"把第 X 件做掉 / 生成方案 / 落地"，进入第二阶段。

# 第二阶段：方案与落地（新增）

**触发**：用户从第一阶段 Top N 中选定一项，或主动说"做掉第 X 件""生成方案""落地""做成工具"。

## 第 6 步：生成方案（可主动，不落盘）
针对选中的那一项，输出一份**具体、可确认**的实施方案，包含：

可调用 `scripts/generate_landing.ps1` 把方案**固化成可开工文件**，而不是只在对话里手写——它会按所选交付形态，生成「方案卡.md + 确认清单.md + 执行骨架」三件套（执行骨架随交付形态选 `run.ps1` / `run.py` / `tool.html` / `task-config.json` / `SKILL.md` / `rpa-steps.md`）。用法示例：
```powershell
# ① 先 dry-run 预览（默认行为：只打印将生成什么、写到哪，不建目录、不写文件）
powershell -ExecutionPolicy Bypass -File "~/.本平台/skills/pc-automation-studio/scripts/generate_landing.ps1" -Name "日报合并" -Delivery python -Spec "合并下载目录每日销售日报" -Files "merge.py"
# ② 用户在第 7 步明确确认后，才追加 -Execute 真正写盘
powershell -ExecutionPolicy Bypass -File "~/.本平台/skills/pc-automation-studio/scripts/generate_landing.ps1" -Name "日报合并" -Delivery python -Spec "合并下载目录每日销售日报" -Files "merge.py" -Execute
```
该脚本**默认 dry-run、只预览不写盘**，只有显式传 `-Execute` 才真正生成落地包文件；脚本本身不执行任何改动命令、不读写用户业务文件。第 7 步确认闸门仍由你把关，且**任何落地类动作一律经此脚本走、禁止绕过脚本在对话里直接手写/直接动盘**。

1. **交付形态**（明确选一种或组合）：
   - 单文件离线 HTML 工具（纯本地、双击即用、不联网）
   - Python 脚本（受管 venv 装依赖，不污染用户环境）
   - PowerShell 脚本（Windows 原生）
   - 定时自动化（automation_update，recurring / once）
   - 新子 Skill（可复用）
   - RPA 流程（playwright-cli / agent-browser）
   - 现成工具兜底（Power Automate / 浏览器插件）
2. **方案规格**：输入是什么、输出是什么、核心逻辑草图、边界与异常处理、隐私立场（本地/离线/不传外网）。
3. **文件清单与落盘位置**：默认放用户当前工作目录或用户指定处；列出将新建/修改的文件名。
4. **工作量与风险**：大致工作量；**是否涉及移动/删除/归档文件**（涉及则标红，进入第 7 步二次确认）。

呈现为一份"方案卡"，语言大白话，**不写任何文件、不跑任何改动命令**。

## 第 7 步：确认（硬闸门，必须）
把方案卡摆出来，**明确要求用户确认**，至少说清：
- 交付形态、落盘位置对不对？
- 涉及的输入/输出理解对不对？
- 若涉及移动/删除/归档：单独列出**受影响文件清单**，逐项目请用户二次确认，并说明将走回收站（非直接删除）。

**此步零副作用**：不创建文件、不执行命令、不改任何状态。用户未明确说"确认/做吧/可以"，绝不进入第 8 步。

**机械闸门（不靠自觉，脚本兜底）**：这一步对 `generate_landing.ps1` 的调用一律**不带 `-Execute`**（即 dry-run），脚本只会打印预览、一个文件都不落盘。即使用户催促"别预览了直接做/赶紧落地"，**不带 `-Execute` 也物理上写不了盘**——把"等用户确认"从一句纪律变成脚本的默认行为。用户的明确确认，唯一兑现方式就是下一步显式追加 `-Execute`。

## 第 8 步：落地执行（确认后才动手）
用户确认后，按要求实施。**落地类动作一律经脚本执行、并显式带 `-Execute`**：用第 7 步 dry-run 预览过的同一组参数重跑 `generate_landing.ps1`，仅在此时追加 `-Execute` 真正写盘；**禁止**绕过脚本在对话里直接手写文件、直接调删除/移动命令。脚本默认 dry-run 这一闸门保证：只要没带 `-Execute`，就一定是预览、不会真落地。执行期安全铁律：

- **默认只读/新建**：新工具、新脚本、新定时任务都走"新增"，不动用户既有文件。
- **动文件必须二次确认 + 走回收站（机械纪律）**：任何移动/删除/归档，必须第 7 步已逐项目确认；用系统回收站（`gio trash` / `trash` / Recycle Bin API），**绝不**用 `rm -rf`、`del /S /Q`、`shutil.rmtree`、通配符批量删。涉及移动/删除的落地包，生成时必须对脚本加 `-MoveDelete`，让确认清单显式列出受影响文件；执行骨架里也按"先样本、后批量、误删可从回收站恢复"编写。
- **敏感文件本地离线**：照片/隐私类素材默认离线处理，不调外网、不上传；批量处理前若含人脸/隐私，提醒先打码。
- **依赖隔离**：Python 依赖装进受管 venv；Node 依赖装进受管 workspace；不全局污染。
- **小批量验证**：动文件类操作先拿 1–3 个样本试跑，确认无误再继续；每批验证。
- **完成后交付**：给出「怎么用 / 怎么跑 / 怎么停」说明，以及**回滚方式**（如误归档如何从回收站恢复）。

## 注意事项
- 本技能**既能诊断也能落地**，但落地必须"先方案、后确认、再动手"，确认闸门不可跳过。
- **不准就不列**：证据不足、或用户说"不烦"的，坚决不进 P0，宁可向用户多问一句，也不要用一堆泛泛建议凑数。
- 盘点是手段，价值在"建议 + 交付"。若用户已口述清楚使用习惯，第一阶段可跳过第 1 步直接给建议（但 ROI 仍需追问真实数字）。
- 涉及外部账号、API Key、企业内网系统的自动化，必须提示用户自行保管凭据，不在对话里明文收集。
- **平台说明**：配套盘点脚本 `lightweight_inventory.ps1` 基于 Windows PowerShell，在 Windows 上可直接运行；macOS / Linux 用户可用等价只读命令（如 `ls` 顶层、`ps`/`Get-Process` 替代、`crontab -l` 看定时任务）收集同类信号，诊断流程不受影响。
