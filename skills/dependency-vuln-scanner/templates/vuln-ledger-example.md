> 目标：漏洞清零（「漏洞主表」所有行变「已修复/已移除」+ 复扫 🟢 A 级）。按 EPSS 分批；同一依赖的多个 CVE 合并成一次升级（升到覆盖所有 CVE 的最小修复版本）。

| 批次 | 动作（依赖 → 目标版本） | 覆盖 CVE | 修复命令 | 状态 | 完成日期 |
|------|------------------------|----------|----------|------|----------|
| 第1批（立即：🔴 正在被攻击 / ⛔ 恶意包） | cross-env-tools → 移除；lodash → 4.18.0 | MAL-2022-36067, CVE-2021-23337 | npm uninstall cross-env-tools；npm install lodash@4.18.0 | 完成 | 2026-09-08 |
| 第2批（近期：🟠 较可能被利用 1%~10%） | express → 4.17.3；minimist → 1.2.6 | CVE-2022-24999, CVE-2021-44906 | npm install express@4.17.3；npm install minimist@1.2.6 | 完成 | 2026-09-15 |

「批次」状态取值：未开始 / 进行中 / 完成。每完成一批，更新本表状态 + 完成日期，并同步「漏洞主表」对应行的「状态」「修复日期」，再复扫刷新「清零进度」。
> 说明：第3批延后是**用户自己的排期选择**（低风险、安排在下周），**不是技能要求等待**——用户若想一次修完，可与第2批合并执行。

## 使用说明

1. 每次扫描/复扫后，按扫描结果更新「漏洞主表」各行的「状态」；
2. 首次扫描后，AI 生成「清零路线图」写入本表，并给「漏洞主表」每行标注「批次」；
3. 每完成一批，把该批「状态」改为「完成」+ 填「完成日期」，同步更新「漏洞主表」对应行的「状态」「修复日期」，并复扫刷新「清零进度」；
4. 复扫时按 `(依赖, CVE)` 键与上次对比，再更新「扫描历史」和「清零进度」；
5. 每次对话结束前，与用户约定「下次复扫日期」并写入基本信息；
6. 状态为「已修复 / 已移除」的行保留在台账中（用于追踪历史，不要删行）。

## 这个示例演示了什么

- **一次扫描 → 分批路线图**：5 个漏洞（含 1 个恶意包）按 EPSS 分成 3 批，恶意包与 EPSS≥10% 的优先；
- **复扫 → 基线对比**：2026-09-08 复扫显示「新增 0 / 已修复 2 / 仍存在 3」，用户一眼看到进展；
- **路线图 ↔ 台账联动**：第1、2 批「完成」后，主表对应行同步变「已修复/已移除」，清零进度 0/5 → 2/5 → 4/5；
- **清零目标可追踪**：还剩第 3 批（node-fetch）→ 修完复扫成为 🟢 A 级即清零。
- **分批只是优先级建议**：第3批可以并入第2批一次修完；分批仅用于「一次修不完」时排序，不是让用户拖延。
